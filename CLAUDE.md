# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is the source for a Bayesian adaptive randomized N-of-1 crossover trial at Maya Care and Grow (an early autism intervention center in Agartala, India). The trial finds the optimal pre-session preparation condition (NoPrep, Calming, Stimulating, ChildChoice) for maximizing each child's engagement. Pre-registered on OSF; data collection runs through June 2026.

The repo is a monorepo of three loosely coupled parts:

- **`analysis/`** — R / Bayesian pipeline (the scientific core). Power simulations, sensitivity analyses, and the main trial analysis.
- **`paper/`** — LaTeX manuscript and pre-registration appendix (uses the `rho` document class in `paper/rho-class/`).
- **`web/`** — Next.js 16 / React 19 / TypeScript site (https://rct-autism.vercel.app) with layman explanations and dynamic results.

`docs/protocol.md` is the authoritative trial protocol — read it to understand the statistical design, stopping rules, and conditions before changing analysis logic.

## Analysis pipeline (R)

Requires **R >= 4.2** and a C++ compiler (`cmdstanr` is the `brms` backend). Reproducibility is managed by `renv` (`.Rprofile` activates it automatically).

```r
# One-time setup: installs packages from renv.lock (or initializes if missing)
source("analysis/00_initialize_project.R")

# Run an analysis stage (always from the repo root so `here` anchors paths)
rmarkdown::render("analysis/01_power_analysis.Rmd")
```

The `.Rmd` stages run in sequence and share `analysis/utils/`:

| Stage | Purpose |
|:------|:--------|
| `01_power_analysis.Rmd` | Simulation-based power across child archetypes; justifies the 28-session cap |
| `02_prior_sensitivity.Rmd` | Informative vs. flat priors on stopping decisions |
| `03_covariate_sensitivity.Rmd` | Robustness to nuisance covariates (time of day, assistant) |
| `04_main_analysis.Rmd` | Processes the real collected trial data |

### Architecture of `analysis/utils/`

`main.R` is the orchestration entry point: it `source()`s the utility files in order, sets `set.seed(42)`, fits the model, and writes summaries/plots/stopping results. The utilities:

- `model.R` — `fit_model_fresh()` (compiles + fits from scratch) and `fit_model_update()` (re-fits a compiled template ~10× faster). Holds the model equation `engagement ~ prep + teacher + age + (1 + prep || child_id)` and `SHARED_PRIOR`. The `||` keeps random intercept/slopes uncorrelated.
- `stop_criteria.R` — `check_stopping_per_child()` implements the three per-child stopping rules from the protocol (Superiority, AIPE/precision, ROPE/null). Works on posterior draws, combining fixed effects with `r_child_id[...]` deviations.
- `parse_form_data.R` — **the data ETL**. Reads raw `data/form_data.csv`, pairs each child-day's "prep" and "rating" rows into one session, computes `engagement` as the mean of `rating_5/15/30`, anonymizes child/assistant names via `data/child_map.csv` and `data/assistant_map.csv`, validates ranges, and writes `data/sessions.csv` (anonymized, the analysis input) plus `data/sessions_with_child_names.csv`.
- `constants.R` — canonical `PREP_PARAMS` / `ALL_PREPS` mapping prep condition names to model coefficient names.
- `sim.R`, `power.R`, `sensitivity.R` — simulation and sensitivity helpers; `multiprocessing.R` sets up `furrr`/`future` parallelism; `plotting.R` builds forest/box plots (optionally as TikZ for the paper).
- `data.R` — `save_csv()` writes timestamped CSVs to `results/draft/`.

### Reproducibility notes

- Seed `42` is used across simulations. The model fit itself uses `seed = 123`.
- `FORCE_REPRODUCIBILITY <- FALSE` in `model.R`: setting it `TRUE` disables threading because `cmdstanr` threading breaks exact reproducibility.
- Generated outputs land in `results/` (CSV/TikZ/PDF for the manuscript); `data/sessions*.csv` are regenerated by `parse_form_data.R` — edit the raw source or the parser, not the outputs.
- Lint R with `lintr` per `.lintr`: snake_case or SCREAMING_SNAKE_CASE object names, 120-char lines.

## Web app

All web commands run **from the `web/` directory** with **yarn** (Node 20+).

```bash
cd web
yarn install --frozen-lockfile
yarn dev          # dev server, hot reload, http://localhost:3000
yarn lint         # eslint, --max-warnings 0
yarn lint-fix     # eslint --fix
yarn typecheck    # tsc --noEmit
yarn build        # production build
```

Conventions (enforced in code review): kebab-case filenames, PascalCase components named after their file, `use`-prefixed camelCase hooks, no `any` (prefer `unknown`), Tailwind utility classes for styling. `eslint-plugin-simple-import-sort` orders imports — run `yarn lint-fix`.
